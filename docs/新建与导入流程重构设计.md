# 浮生流年 v4.1 — 新建书与导入书流程重构设计

> 日期：2026-07-28
> 前置阅读：《问题诊断与改造方案.md》（P0 修复）、《共创式流程重构设计.md》（v4 三层架构 + 章节状态机 + 反馈飞轮）。
> 本篇回答三个问题：
> ① 新建一本书的流程怎么重构，既完整表述我的意思、又放开 AI 的能力，还能让傻子变大神；
> ② 导入一本小说怎么完整拆解，支撑续写 / 仿写 / 同人；
> ③ 两条入口如何殊途同归——导入的作品建成专门知识库，写的时候用得上。

---

## 一、现状核心结论（来自代码探查）

**新建书链路**（`ai_assist.py::generate_story_foundation` + `new-book-wizard.tsx`）：
- foundation 一次性生成全书三段 + 第一卷 + 前 10 章方向，用户以**编辑表单**的方式确认——傻瓜用户面对十几个字段根本不知道改什么，等于没有真正的意图表达；
- 创作宪章是从输入**自动拼装**的（`worldbuilder.py:424`），`ai_mandate`、`chapter_test` 甚至是写死的固定文案，向导里没有独立确认环节；
- 三种模式（灵感/陪跑/懒人）三套代码互不复用；`book-blueprint`/`volume-plan`/`character-cast`/`world-engine` 四个端点已实现但前端从未接线——能力分裂。

**导入链路**（`import_service.py` + `analyzer.py`）：
- 拆解本身做得不错：分章 → 三路 observer + verifier 逐章提取人物/世界规则/伏笔 → 文风指纹（`analyze_style`）→ 断点分析（`analyze_breakpoint`）；
- **但拆解成果续写时几乎全被浪费**（三大断裂，`imports.py:255-342`）：
  1. 原作正文只留在 `ImportedChapter`，不进 Project 的章节与检索——续写时 `recent_chapters`、RAG 全为空；
  2. 文风指纹只存进 `StyleReference` 表，而 `build_context_pack` 只读 `project.style_profile`——**原作文风对续写正文实际上零作用**；
  3. 伏笔只留在 `extracted_data` JSON，不进 `Foreshadowing` 表——promise_ledger 拿不到原作未收伏笔。
- 只有"续写/同人"两种用途，没有"仿写"；写作知识库（方法卡）是全局手艺库，与具体作品无关联。

**一句话诊断：新建书是"填表式一次性表达"，导入书是"拆完就扔"。两者都没有把成果沉淀成写作时真正用得上的资产。**

## 二、统一心智模型：一切入口都在生产同一个"项目种子"

v4.1 的核心抽象：不管你是从零开始还是导入一本书，**建项的本质都是把"项目种子（Project Seed）"填满**，之后进入同一个章节状态机（v4 设计的 BRIEF→GATE→DRAFT→…）。

项目种子 = 四包资产：

| 资产包 | 内容 | 新建书的来源 | 导入书的来源 |
|---|---|---|---|
| **心意包** | 意图锚点、品味档案、范例库、创作宪章 | 意图访谈 + 品味测试 | 原作风格层拆解 + 用户确认"哪些要保留" |
| **事实包** | 人物卡、世界规则、时间线、伏笔账本、Wiki | AI 提案 + 用户裁决 | 原作事实层拆解（直接迁移） |
| **蓝图包** | 全书弧线、第一卷卷纲、开篇方向 | 根基共建（选择题式） | 断点分析 → 续写蓝图提案 |
| **叙事资产包** | 可检索正文、摘要链、语感卡、场景范例 | 空（从第 1 章开始积累） | 原作全文入库 + 拆解产物 |

**殊途同归的含义**：两条入口只是"填种子的方式"不同，种子结构完全相同、写作流水线完全相同。这样以后再加第三种入口（比如"从一份旧稿恢复"）也不用改写作侧。

## 三、新建书流程重构：意图访谈制

### 3.1 设计原则：锚点收紧，其余放开

"完整表述我的意思" 和 "放开 AI 的能力" 表面矛盾，解法是**把用户的意思分成两类**：

- **意图锚点（少而硬）**：结局方向、情感内核、不可妥协项、雷点。这些是"你的心意"，AI 永远不许违背，写进宪章、每章注入；
- **自由区（多而软）**：具体情节、配角、支线、世界细节。这些交给 AI 滚动规划，用户只在意图简报里逐章裁决。

现在的问题恰恰是反的：foundation 把前 10 章方向都定死了（伪精确），而真正该锁死的"心意"却是自动拼装没确认过的。

### 3.2 新流程五步（替代现在的三模式）

```
第1步 意图访谈（对话式，5~8 分钟）
  AI 像编辑约稿一样聊天，不是表单：
  "你想写个什么样的故事？随便说，说乱了我来整理。"
  →用户随口说 → AI 复述确认："我听到的是：你想要一个 XX 的故事，
    最在乎的是 XX，绝对不能出现 XX——对吗？哪里不对你直接说。"
  产出：意图锚点（3~5 条）+ 宪章草稿（用户逐条确认，替代自动拼装）

第2步 品味测试（2 分钟，可跳过）
  同一场景 4~6 种写法的短段落，选"最想看"和"最受不了"
  产出：品味档案初版 + 第一批范例库（v4 心意层直接初始化）

第3步 根基共建（选择题式，替代表单编辑）
  AI 基于锚点提案故事根基，每个大件给 2~3 个方案 + 大白话代价：
  "主线我有两个想法：A 复仇线（前期压抑后期爆发，你选过'先虐后爽'，
   应该合你胃口）；B 夺宝线（节奏快但情感浅）。选哪个？"
  逐项裁决：主线弧 → 主角设定 → 世界底色 → 第一卷方向
  产出：全书弧线（只有三段粗线条）+ 第一卷卷纲 + 事实包初版
  ※ 前 10 章方向砍掉——那是伪精确，交给逐章意图简报

第4步 试写样章（关键改动：一次出 2~3 版）
  用不同温度/节奏参数写同一个开篇，用户选最喜欢的 + 说一句为什么
  产出：第一章 + 强品味信号（选中版与落选版的 diff 进反馈飞轮）

第5步 建项
  项目种子四包落库 → 进入章节状态机（默认副驾挡）
```

### 3.3 傻子怎么在这条流程里变成大神

- **全程零术语**：没有"大纲/卷纲/POV"，只有"你想要什么感觉""选 A 还是 B"；
- **每个选择题都带读者体验解释**（"A 更爽但烧伏笔"）——这就是在教节奏、教结构，只是不点名；
- **复述确认**训练用户把模糊感觉说清楚——"AI 理解错了"的每一次纠正，都是用户表达能力的一次练习；
- **多版本试写**训练审美判断——比较是最好的学习；
- 三种旧模式收敛为一条流程的**深浅两档**：懒人 = 访谈只答 2 题 + 全部选"你定"；深度 = 每步都细聊。同一套代码，参数不同。

### 3.4 后端落地

- 砍掉 `guided`/`lazy` 两套独立链路，`generate_story_foundation` 改造为分步端点（复用已实现但未接线的 `book-blueprint`/`character-cast`/`world-engine`，正好归位）；
- 意图访谈用会话式端点（SSE），产出结构化 `intent_anchors`；
- 宪章不再自动拼装：`ai_mandate`、`chapter_test` 由访谈结论生成、用户确认后落库；
- 新表见第六节。

## 四、导入书流程重构：从"拆完就扔"到"作品知识库"

### 4.1 核心概念：作品知识库（Work Codex）

导入一本书后，拆解产物组织成**四层作品知识库**（挂在 `ImportedWork` 下，独立于全局写作手艺库）：

```
作品知识库（Work Codex）
├─ 事实层：人物卡 · 关系网 · 世界规则 · 时间线 · 伏笔账本（含未兑现清单）
├─ 叙事层：全文分块 embedding（可检索原文证据）· 滚动摘要链 · TOC 树
├─ 风格层：文风指纹 · 场景范例库（按类型抽的原文段落）· 人物语感卡（每人 5~10 句台词样本）
└─ 技法层：叙事基因卡——这本书的"写法"（爽点间隔 · 章末钩子模式 · 视角习惯 ·
           冲突升级节奏 · 开篇模式），由 LLM 对拆解统计归纳生成
```

对比现状：事实层已有（observer 拆解），叙事层的 embedding/摘要链/TOC **没做**，风格层只有指纹没有范例库和语感卡，技法层完全没有。

### 4.2 拆解流水线补强（在现有 `run_full_analysis` 上加四步）

1. **叙事层建设**：`ImportedChapter` 全文分块 + embedding（复用 `ChapterChunk` 机制）；每 10 章生成段摘要、按卷生成卷摘要（与 v4 滚动摘要链同一套代码）；生成 TOC 树；
2. **范例抽取**：每章按场景类型（打斗/对话/心理/过渡/高潮）抽代表性段落 → 场景范例库；
3. **语感卡**：每个主要人物抽台词样本 + LLM 归纳语感描述 → `character_voice_cards`（v4 已规划此表，导入是它的第二个数据源）;
4. **叙事基因卡**：对全书做统计（章均字数、对话占比曲线、爽点分布）+ LLM 归纳 → `narrative_dna`。

### 4.3 三种用途 = 四层知识库的三种组合

| 用途 | 事实层 | 叙事层 | 风格层 | 技法层 | 说明 |
|---|---|---|---|---|---|
| **续写** | ✅ 全继承 | ✅ 全继承 | ✅ 全继承 | ✅ 继承 | 断点分析变成第一份意图简报："原作停在 XX，有 N 个未收伏笔，我建议先收 XX——你觉得呢？" |
| **同人** | ⚙️ 用户勾选分叉点（"从第 200 章分叉""某人不死"） | ✅ 分叉点之前的可检索 | ⚙️ 可选：保持原作文风 or 换自己的 | ⚙️ 可选 | 分叉点之后的事实由状态机重新演化，之前的照常检索 |
| **仿写** | ❌ 不继承（新故事新人物） | ❌ 仅作技法参照检索 | ✅ 风格层作为品味档案底版 | ✅ 技法层全用 | "用《XX》的笔法和节奏写我自己的故事"——走新建书流程，但品味测试/范例库/叙事基因直接从原作预填 |
| （鉴赏） | — | ✅ 可对话检索 | ✅ | ✅ | 附赠：知识库建好后天然支持"这本书为什么好看"的拆书问答，本身就是学习工具 |

**仿写是新增用途**，也是"傻子变大神"的重要路径：把喜欢的书导入 → 技法层告诉你它的爽点节奏和钩子模式 → 你的新书直接站在这个骨架上写自己的故事。

### 4.4 修复三大断裂（续写场景，必做）

1. 原作章节正文 → 以"前史章节"身份进入续写项目的检索范围（`chapter_chunks` 打 `source=imported` 标记，context pack 的 RAG/TOC 对它们可见）；
2. 原作文风 → 不再只存 `StyleReference`：风格层直接初始化续写项目的**品味档案 + 范例库**（v4 心意层），从而经由正常渠道注入每章 prompt；
3. 原作未收伏笔 → 批量迁移进 `Foreshadowing` 表（status 沿用，planted_chapter 标负数或前史编号），promise_ledger 立即可见。

### 4.5 导入后的确认流程（用户可控点）

拆解完成 → 报告页（已有）之后加一步**"知识库校对"**：
- AI 列出置信度低的条目（"我不确定 XX 是死了还是失踪，原文见第 89 章这段"）让用户裁决；
- 用户可以删掉不想要的设定、改人物卡——这既是纠错，也是"表达心意"（同人尤其需要）；
- 校对结果全部进决策记忆。

## 五、殊途同归：统一入口流程图

```
新建书                          导入书
  │                               │
  意图访谈+品味测试                上传/外部逆向 → 四层拆解 → 知识库校对
  │                               │
  根基共建（选择题）                选用途：续写 / 同人 / 仿写
  │                               │        （仿写跳到左边"根基共建"，
  试写样章（多版本选）               │          带着原作风格层+技法层）
  │                               │
  └────────→ 项目种子（四包）←────────┘
                  │
        心意包 · 事实包 · 蓝图包 · 叙事资产包
                  │
        同一个章节状态机（v4：BRIEF → 用户裁决 → 起草 → 自审 → 验收 → 发布）
                  │
        同一个反馈飞轮（越写越懂你）
```

写作时四层知识库的用法（context pack 注入策略）：
- **事实层** → canon/wiki 通道（已有机制）；
- **叙事层** → RAG/TOC 通道（已有机制，导入章节加入索引即可）；
- **风格层** → 心意层通道（品味档案 + 场景匹配范例，v4 Phase 2 的注入器）；
- **技法层** → writing_guidance 通道（与全局方法卡并列，但标注"来自《原作名》"，检索时项目专属技法卡优先于全局卡）。

## 七、实施路线（衔接 v4 的 Phase 编号）

**Phase 1.5 — 修导入三大断裂（最小改动、立竿见影，可与 Phase 1 并行）**
原作正文进检索 + 伏笔迁移 + StyleReference 注入 context（临时直通，等 Phase 2 心意层建好后改走品味档案通道）。

**Phase 2.5 — 新建书意图访谈制（依赖 Phase 1 的简报/裁决 UI 组件）**
意图访谈端点 + 宪章确认步 + 根基共建选择题化 + 多版本试写；三模式收敛为深浅两档。

**Phase 3.5 — 作品知识库四层完整版（依赖 Phase 3 摘要链代码）**
叙事层（embedding/摘要链/TOC）+ 范例抽取 + 语感卡 + 叙事基因卡 + 知识库校对页 + 仿写入口。

**Phase 4 不变**（成长系统），但"拆书问答"（对导入作品的鉴赏对话）可作为低成本附赠先做。

## 八、一句话总结

**新建书从"填表"改成"访谈 + 选择题"——锚点��紧表达心意，自由区放开 AI 能力；导入书从"拆完就扔"改成"四层作品知识库"——事实供一致性、叙事供检索、风格供文风、技法供仿写；两条路殊途同归到同一个项目种子和同一个章节状态机，而傻子变大神的秘密，是让他在每一个环节都只做带解释的判断题，判断得越多，他就越懂写作。**
