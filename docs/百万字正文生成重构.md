# 百万字正文生成重构

更新时间：2026-07-24

## 1. 研究范围

本轮从写作指导库约 500 份资料中，精读了期待感、大纲与细纲、人物刻画、
情节因果、冲突、节奏、铺垫、伏笔、对话、代入感、女频升级与感情线、
金手指限制以及长篇作者访谈等互补材料，并用生产数据库中的首章生成记录
核对当前实现。

资料不是权威规则。以下内容被明确排除为反例：固定章数制造高潮、为减慢节奏
而注水、卡文就杀角色或换地图、伏笔可以永不回收、用套路表代替人物逻辑。

## 2. 可靠写作原则

1. 长篇靠承诺链而不是字数维持。读者应同时看见本章即时问题、当前事件弧目标、
   本卷承诺和全书核心问题；一个承诺兑现前，要自然露出下一层问题。
2. 情节的最小单位不是事件，而是人物在具体环境中为了即时欲望，面对阻力采取
   行动、作出选择并承受结果。结果必须制造下一场的新需求。
3. 人物靠稳定的欲望、方法和底线形成辨识度，靠压力下的不同选择形成成长。
   标签、外貌清单和作者评价不能替代选择。
4. 高潮是多条与主线有关的因果线收拢并兑现，不是突然提高音量或增加打斗。
   铺垫必须同时承担当前场景功能，不能只为未来储存信息。
5. 节奏是信息、压力和结果的密度变化。关键选择与后果可以放慢，重复过程可以
   压缩；生活摩擦用于恢复注意力和显露人物，不等于注水。
6. 对话双方必须各有目的、顾虑和不能直说的内容。有效对话至少改变关系、行动、
   信息或读者对人物的判断之一。
7. 长篇大纲只封存核心承诺、人物不可逆变化和终局方向。卷纲滚动规划，章纲靠近
   执行时细化；偏离旧方案可以，但必须说明新方案如何更好地服务原始心意。

## 3. 当前实现的生产证据

- 写作知识库有 499 个文档、14846 个 chunk，但向量为 0。
- 14846 张方法卡全部是按 chunk 首行机械生成的草稿，已发布方法卡为 0。
- `build_context_pack` 只有在命中已发布方法卡后才读取原文，因此生产首章的
  `writing_guidance` 完全为空。
- PageIndex 没有进入章节 Context Pack；首章失败发布后也没有章节 chunk 和索引任务。
- 候选稿选择先比较是否落在 2800 至 5500 字，再比较审稿分数，字数事实上优先于质量。
- “去 AI 味”只删除少量连接词；世界规则、POV 和风格门主要依靠脆弱正则和对话比例。
- 审稿模型用自报总分决定发布，并最多触发三轮串行改写。生产首章因此运行 25 分钟，
  仍因字数、自评分和 Observer 冲突进入 `review_required`。

## 4. 目标流水线

```text
确认章纲
  -> 装配创作简报
     - 作者宪章和本书文风合同
     - 当前章场景契约
     - 当前人物状态与知识边界
     - 最近两章精确承接
     - PageIndex 选出的跨卷相关节点
     - 混合检索返回的必要原文片段
     - 2 至 4 张已审核写作方法卡
     - 临期承诺、伏笔和本卷目标
     - 有明确研究问题时才加入联网资料
  -> 一次完整初稿
  -> 确定性硬检查
     - JSON/正文存在
     - 确认章纲中的必需场景和结果是否有文本证据
     - Canon 明确事实、人物知识边界、时序和存亡冲突
     - 作者不可妥协项
  -> 一次证据化叙事审读
     - 只报告带原文证据的问题
     - hard: 事实冲突、人物无理由背叛、因果缺口、核心承诺未兑现
     - soft: 文笔、节奏、对话和信息释放建议
  -> hard 问题存在时最多一次定向修复并复核对应问题
  -> 保存可读稿
  -> 提取状态变化并做证据校验
  -> 发布 Canon / Wiki / 承诺账本 / 检索索引
```

字数只作为写作目标和统计信息，不再是发布阻断门。只有明显截断或缺失整个必需场景
才构成硬错误。模型自报分数不再决定发布；软问题显示给作者，但不阻断状态入账。

## 5. 四类知识的职责

### 写作指导 RAG

原始教程只用于离线研究、方法卡编译和来源追溯。每章不直接塞入随机原文。方法卡按
任务检索，例如“首章读者定位”“关系对话潜台词”“升级能力限制”“高潮收线”，并且
必须包含适用条件、操作步骤、可观察检查、反例和来源 chunk ID。

`qwen3.7-text-embedding` 用于中文语义召回。索引必须记录模型、维度和版本；先探测模型
实际维度，再迁移列和批量回填。向量召回与标签、标题和中文子串召回做 RRF，不让向量
单独决定答案。

### LLM Wiki / Canon

Wiki 保存相对稳定且可解释的故事事实：人物核心欲望、惯用方法、底线、关系、世界规则
和地点。Current State 保存易变状态。每条动态事实必须指向发布 revision 和正文证据。
教程、联网资料和模型猜测绝不能写进故事 Canon。

### PageIndex

PageIndex 处理“在哪一卷、哪条事件弧、哪些历史章节里找答案”。它在章纲生成和跨卷记忆
装配时使用，不在每个句子生成时反复调用。导航应支持多个相关分支，先返回最小充分节点，
再对节点覆盖的章节做精确检索；不能像当前实现只沿第一个候选一路向下。

### 联网研究

联网只解决可核验的现实事实，例如历史制度、职业流程、地理、技术、法律和物件细节。
虚构世界、人设和情节方向不使用网络投票。搜索由章纲显式产生研究问题，结果保存 URL、
标题、摘录、检索时间和可信度，作为临时研究笔记；未经作者或正文证据确认不进入 Canon。
没有配置搜索提供商时跳过，不阻断小说写作。

## 6. 百万字不崩的状态模型

每章除了正文，还要维护三本账：

- 事实账：人物位置、持有物、伤势、身份、关系和知识边界。
- 承诺账：读者正在等待什么、首次提出章节、最近提醒章节、计划兑现窗口、当前进度。
- 因果账：本章关键选择、直接结果、新产生的压力以及关联的事件弧。

伏笔只是承诺账的一种。普通章末问题、关系期待、升级目标和主题选择也必须能登记、推进、
兑现或明确放弃。卷末再规划以这三本账为输入，而不是只读最近六章摘要。

## 7. 验收标准

1. 一章正常只调用一次 Writer 和一次 Auditor；只有 hard 问题才调用一次 Repair。
2. 同一章生成不因 2800 字门槛自动扩写或反复重写。
3. 生成日志能展示真实阶段、耗时、检索来源和修复原因。
4. 指导库检索至少返回一张已审核方法卡，并能追溯源文件和 chunk。
5. PageIndex 能同时返回两个相关事件弧，并据此找到对应历史正文。
6. Observer 冲突保留为待核状态，不因非关键抽取分歧阻断可读正文发布。
7. 硬冲突不得更新 Canon；软文笔问题不得阻断章节保存和下一步人工修改。
8. 用固定章纲生成多版样本，人工盲评人物一致性、场景因果、读者定位、承诺兑现和自然度，
   不再以模型总分作为唯一质量指标。
