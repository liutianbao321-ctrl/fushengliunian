# 浮生流年 v4 — 共创式流程重构设计

> 日期：2026-07-28
> 目标：从"自动流水线代工厂"重构为"懂我心意的 AI 共创作家"。
> 三个核心诉求：① AI 明白我的心意；② 我有自主可控权；③ 傻子也能变成大神作家。
> 前置阅读：《问题诊断与改造方案.md》（P0 修复是本方案的地基，先修再改）。

---

## 一、理念转变：问题出在"哲学"上，不只是代码上

现在的系统是一条**代工厂流水线**：用户在开头填一次设定，然后 AI 按固定 DAG 一章章往外吐，用户只能在章纲确认时点一下"同意"。这个模式有三个先天缺陷：

1. **AI 不知道你的心意**——创作宪章是静态的，写第 1 章和写第 500 章时 AI 对你的了解一模一样。你每次不满意、每次手改一段文字，这些最宝贵的信号全部被丢弃；
2. **你没有真正的控制权**——只有"确认章纲"一个卡点，正文写成什么样你只能事后看，不满意也没有"就改这一点"的通道，只能整章重生成（还因为缓存 bug 生成出一样的）；
3. **它没有让你变强**——系统把所有创作决策藏在黑盒里，你既不知道 AI 为什么这样写，也没机会做真正的创作判断。

**v4 的核心哲学：AI 出执行力，你出判断力，系统负责把你的每一次判断变成 AI 对你的了解。**

写作大神的本质不是文笔（AI 有），而是判断力——知道"这里该爽了""这个人物不该说这种话"。判断力人人都有（读者都会骂书），缺的是把判断变成文字的执行力。所以"傻子变大神"的路径是：**把所有创作决策翻译成大白话选择题，让用户做判断，AI 负责执行，并且永远记住用户的每一次判断。**

---

## 二、新架构总览：三层 + 一个飞轮

```
┌─────────────────────────────────────────────┐
│  心意层（新增）——"AI 凭什么懂你"              │
│  品味档案 · 范例库 · 决策记忆 · 创作宪章(已有)  │
├─────────────────────────────────────────────┤
│  共创层（重构）——"每一章怎么写出来"            │
│  意图简报 → 用户裁决(按挡位) → 分场景起草       │
│  → 自审修订 → 交付验收 → 发布                  │
├─────────────────────────────────────────────┤
│  基座层（保留+补强）——"事实不出错"             │
│  活体Wiki · 状态事件 · 伏笔账本 · 检索          │
│  + 滚动摘要链(新) + 实体温度衰减(修)            │
└─────────────────────────────────────────────┘
        ↑____________反馈飞轮____________↓
   用户每次选择/修改/评分 → 蒸馏 → 更新心意层
```

架构结论先给出：**FastAPI + durable worker + PostgreSQL 的技术底座不用推倒**，SKIP LOCKED、租约、SSE、活体 Wiki、伏笔账本都是好资产。要推倒的是：
- `pipeline.py` 的固定 DAG → **带反馈边的章节状态机**；
- "一次性设定 + 全自动跑" → **三挡控制 + 意图对齐循环**；
- "反馈丢弃" → **反馈飞轮（新增最重要的子系统）**。

## 三、心意层：让 AI 越写越懂你

### 3.1 品味档案（Taste Profile）

一份**由系统自动蒸馏、持续演进**的结构化文档，注入所有写作 prompt。内容分四类：

- **文风偏好**：句子节奏（短促/绵长）、描写密度、对话占比、幽默浓度、"油腻度"红线；
- **叙事偏好**：爽点节奏（多少章一个）、发刀容忍度、感情线浓度、配角戏份上限；
- **雷点清单**：用户明确说过"不要"的东西（如"不要圣母主角""不要突然降智"）；
- **人物心意**：用户对具体角色的期待（"希望她后期黑化""这两人不要成 CP"）。

**来源不是让用户填表**（傻瓜填不了表），而是从三个渠道自动积累：
1. **开书品味测试**：新书向导给用户看 4~6 段不同风格的短文（同一场景不同写法），让他选"最想看的"和"最不想看的"——这直接初始化文风偏好 + 拿到第一批 few-shot 范例；
2. **反馈飞轮蒸馏**（见第五节）；
3. **随口一句话**：用户任何时候在对话框说"最近写得太拖了"，AI 解析后写入档案并复述确认："收到，我会加快节奏，大约每 3 章安排一个小爽点，对吗？"

### 3.2 范例库（Style Exemplars）

品味档案是"规则"，范例库是"样子"。LLM 学样子远比守规则有效（这正是现在 20 条禁止清单失败的原因）。范例来源：
- 品味测试中用户选中的段落；
- **用户手改后满意的段落**（改前 vs 改后的 diff 是最强的品味信号）；
- 用户主动粘贴的"我想要这种感觉"的文字（注意：只用于风格参照，不逐句模仿，规避抄袭）。

每次写作，检索 2~3 段与当前场景类型匹配的范例（打斗场景配打斗范例）注入 prompt，替代现在的禁止清单。

### 3.3 决策记忆（Decision Log）

系统给用户的每一个选择题、用户的每一次选择，全部落库。作用：
- AI 学会预判："这个用户 10 次里有 9 次选'先虐后爽'，以后默认项就按这个出"；
- 决策可回溯："第 120 章为什么杀了这个角色？——第 118 章你选了 B 方案"。

## 四、共创层：每一章的新流程（状态机）

### 4.1 三挡控制——自主可控权的核心

| 挡位 | 用户参与度 | 适合场景 |
|------|-----------|---------|
| **自动挡** | 只在卷边界、重大转折点（主角色死亡/感情线定局）被请示，其余全自动 | 系统已经很懂你之后；日更赶稿 |
| **副驾挡（默认）** | 每章开写前看一份 30 秒能读完的"意图简报"，一键通过或改两句 | 大多数时候 |
| **手动挡** | 逐场景协作：AI 写一场 → 你看一场 → 可改可批注可要求重写 | 关键章节（大高潮、大转折）|

关键设计：
- **随时换挡**，粒度到章："这一卷自动挡，但第 340 章大决战我要手动"；
- **自动挡不是放弃控制**：AI 在自动挡遇到"决策记忆中没有先例的重大抉择"时必须停下请示，而不是自作主张；
- 挡位存储在 `control_settings`，worker 执行到用户门时按挡位决定"等待用户"还是"自动通过"。

### 4.2 意图简报（Intent Brief）——对齐心意的关键动作

每章开写前，AI 生成一份大白话简报（不是章纲那种术语文档）：

> **第 87 章我打算这样写**：上一章林昭拿到了残卷，这一章他会发现残卷是假的。我想把"发现"放在章末，前面 2/3 铺他的得意和门派的庆功，反差会更狠。风险是节奏偏慢。
> **另外两个写法**：A. 开头就发现是假的，全章写他隐忍装傻（更爽，但烧掉了下一章的悬念）；B. 让苏檀先发现、瞒着他（给感情线埋刺，但你上次说过不想让苏檀有秘密）。
> **本章会动的伏笔**：残卷真伪（第 62 章埋的）推进到"揭穿"。

用户的操作只有三种：✅ 就这样写 / 🔀 选 A 或 B / ✏️ 用一句话改（"按你的写，但把发现提前到 3/4 处"）。

这就是"傻子变大神"的日常形态：**用户每天只做 30 秒的判断题，但每道题都是真正的创作决策，且 AI 讲清楚了各选项的读者体验代价**——做一年判断题，用户自己也学会了什么叫节奏、什么叫伏笔。

### 4.3 章节状态机（替代固定 DAG）

```
BRIEF（生成意图简报）
  → GATE:用户裁决（副驾/手动挡等待；自动挡按决策记忆自动选）
  → DRAFT（按 beat 分 2~3 段起草，每段带前段已写正文，纯文本输出）
  → SELF_REVIEW（critic 带证据自审 + 反 AI 指标计算）
      ├─ 通过 → DELIVER
      ├─ 可修复 → REVISE（失败理由注入，定向重写，≤2 轮）
      └─ 结构性失败 → 回 BRIEF（带失败原因重新规划，≤1 轮）
  → DELIVER（���付预览）
  → GATE:用户验收（手动挡逐场景已验过则跳过；自动挡直接过；
      副驾挡可配置"直接发布，事后可改"）
  → PUBLISH（状态提取 → Wiki → 索引 → 摘要链更新，同事务）
  → COLLECT（反馈采集：用户改动 diff、评分、批注 → feedback_events）
```

与现有 pipeline 的本质区别：
1. **每条失败边都携带"失败理由"进入下游节点的输入**（同时修掉 input_hash 缓存问题——hash 计入 attempt 与反馈内容）；
2. **用户门是一等公民**，状态机可在 GATE 停留任意久（worker 释放租约，用户操作后重新入队），不占资源；
3. **章失败不停全书**：结构性失败 2 轮仍不过 → 该章进"待用户处理"队列并推送通知，项目不 paused；
4. 状态机每个状态仍是 durable worker 的可恢复节点，崩溃恢复语义不变。

### 4.4 事后修改通道（现在完全没有）

发布后用户随时可以：
- **划选一段 → "帮我改成 XX 感觉"**：AI 局部重写，产生新 revision，同时这个 diff 进反馈飞轮；
- **说一句"第 80~85 章太水了"**：AI 给出压缩合并方案，确认后执行（状态事件按追加式修正，Wiki 重建已有能力支持）。

## 五、反馈飞轮：整个 v4 最重要的新子系统

```
采集 → 蒸馏 → 注入 → 验证
```

1. **采集**（`feedback_events`，append-only）：
   - `edit_diff`：用户手改正文的前后对照；
   - `choice`：意图简报/决策点上的选择；
   - `rating`：章末一键评分（🔥好看 / 😐一般 / 👎不行，可选一句话）;
   - `comment`：随口的自然语言反馈。
2. **蒸馏**（新增定时任务，每积累 N 条或每 5 章触发一次）：
   LLM 读最近的 feedback_events + 当前品味档案 → 输出品味档案的**增量修订**（新增规则/强化规则/删除失效规则）+ 候选范例段落 → 写入新版本 `taste_profiles`（保留版本历史，可回滚）。
3. **注入**：所有 BRIEF 和 DRAFT 的 prompt 都带上最新品味档案 + 场景匹配的范例。
4. **验证**：蒸馏出的新规则先标记为 `tentative`，连续 3 章用户没有负反馈才转正——防止一次偶然的修改被过度泛化。

这个回路是"AI 越写越懂你"的全部秘密，现在的系统 0% 实现。

## 六、数据库补充

新增 8 张表（沿用现有 SQLAlchemy + Alembic 体系）：

| 表 | 关键字段 | 作用 |
|---|---|---|
| `taste_profiles` | project_id, version, rules(JSONB), status(active/tentative), distilled_from | 品味档案（带版本） |
| `style_exemplars` | project_id, scene_type, content, source(taste_test/user_edit/user_upload), embedding(vector), approved | 范例库，按场景类型检索 |
| `feedback_events` | project_id, chapter_id, type(edit_diff/choice/rating/comment), payload(JSONB), distilled(bool) | 反馈原始流水，append-only |
| `decision_points` | project_id, chapter_id, question, options(JSONB), chosen, decided_by(user/auto), rationale | 决策记忆 |
| `intent_briefs` | chapter_id, content, alternatives(JSONB), status(pending/approved/edited/auto), user_note | 意图简报与裁决结果 |
| `rolling_summaries` | project_id, level(arc/volume), start_chapter, end_chapter, content, version | 滚动摘要链（10 章一段 + 卷） |
| `character_voice_cards` | entity_id, dialogue_samples(JSONB), voice_notes, updated_chapter | 人物语感卡：台词样本+语感描述，防人物说话走形 |
| `control_settings` | project_id, scope(project/volume/chapter), scope_id, gear(auto/copilot/manual), gate_overrides(JSONB) | 三挡配置 |

改造现有表：
- `chapters`：加 `brief_id`、`gear_used`、`user_rating`；
- `entity_temperatures`：加衰减逻辑（发布时按 `current - last_referenced` 降级 warm/cold）；
- `generation_runs`：节点 input_hash 计入 attempt + 反馈内容（修缓存 bug）。

不需要换数据库：PostgreSQL + pgvector 完全够用（范例库 embedding 复用 pgvector）。MinIO 保持现状即可。

## 七、傻子→大神：成长路径的产品化

系统对用户的画像不是静态的"傻瓜前端"，而是**三阶段渐进**：

1. **读者阶段（0~50 章）**：只做选择题和评分。AI 的意图简报里每个选项都用"读者体验"解释（"更爽但烧伏笔"），用户在选择中建立节奏感；
2. **监制阶段（50~300 章）**：系统开始在简报里问更深的问题（"这条感情线你想什么时候收？"），并展示"你过去的选择模式"（"你偏好慢热型发展，本卷高潮我建议放在…"）——用户开始有自己的方法论；
3. **作家阶段（300 章+）**：用户可以直接改品味档案、写场景批注、手动挡精修关键章。此时 AI 退居执行位。

配套一个轻功能：**"为什么这样写"按钮**——任何一段正文点开，AI 用两句话解释这段的技法意图（"这里用短句是因为追逐戏要压迫感"）。这是内嵌的写作课，成本极低（复用 critic 的分析能力）。

## 八、实施路线（每阶段都独立可用）

**Phase 0 — 地基修复（先做，1~2 天）**
即《问题诊断与改造方案.md》P0：提温、正文去 JSON、max_tokens、修 Guardian 缓存 bug、humanizer LLM 化。不做这步，后面一切白搭。

**Phase 1 — 意图简报 + 三挡控制（核心体验成型）**
- 新表：`intent_briefs`、`control_settings`、`decision_points`；
- pipeline 改造为状态机，加两个用户 GATE（worker 等待/恢复语义）；
- 前端：简报卡片 + 三选项 + 换挡开关（复用现有 SSE 推送）。

**Phase 2 — 反馈飞轮（越写越懂你）**
- 新表：`feedback_events`、`taste_profiles`、`style_exemplars`；
- 章末评分 + 正文划选修改通道 + diff 采集；
- 蒸馏定时任务 + prompt 注入器（品味档案 + 场景范例替代禁止清单）。

**Phase 3 — 长篇支撑补强**
- `rolling_summaries` 摘要链 + 实体温度衰减 + 卷边界自动再规划（含 replan 过滤 bug 修复）+ `character_voice_cards`；
- 开书品味测试向导。

**Phase 4 — 成长系统**
- 三阶段渐进式简报深度、"为什么这样写"按钮、决策模式回顾。

## 九、一句话总结

**旧系统在解决"AI 怎么把小说写完"，v4 解决的是"AI 怎么把你心里那本小说写出来"——用意图简报对齐每一章的心意，用三挡拨杆把控制权始终留在你手上，用反馈飞轮把你的每一次判断变成 AI 的长期记忆，让判断力代替执行力成为创作的唯一门槛。**
